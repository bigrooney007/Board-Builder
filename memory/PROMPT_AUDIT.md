```python
def profile_context_text(profile_data: dict, lead: dict = None) -> str:
    parts = []
    if profile_data.get("mission"):
        parts.append(f"MISSION STATEMENT (use this exact saved mission wherever the mission belongs — never write a placeholder for it): {profile_data['mission']}")
    if profile_data.get("organization_name") and not lead:
        parts.append(f"ORGANIZATION NAME: {profile_data['organization_name']}")
    if lead:
        board_type = (lead.get("answers") or {}).get("board_type", "") or (profile_data or {}).get("board_kind", "")
        if board_type:
            parts.append(f"SELECTED BOARD TYPE (use matching terminology in everything you write): {board_type}")
        parts.append("PUBLIC RECRUITMENT FORM:\n" + json.dumps({k: lead.get(k) for k in ["organization", "website", "city", "state_region", "country"]} | (lead.get("answers") or {}), indent=1, default=str))
    if profile_data:
        parts.append("CONFIRMED MODULE 1 RECRUITMENT PROFILE:\n" + json.dumps(profile_data, indent=1, default=str))
    return "\n\n".join(parts) if parts else "No profile information available."

```

```python
def application_context_text(application: dict, include_cv: bool = True) -> str:
    answers = application.get("answers", {})
    snapshot = application.get("profile_snapshot", {})
    parts = ["APPLICANT APPLICATION:\n" + json.dumps({**snapshot, **answers}, indent=1, default=str)]
    if include_cv and application.get("cv_text"):
        parts.append("APPLICANT CV (extracted text):\n" + application["cv_text"][:15000])
```

## §7 PROMPT CONFLICTS FOUND (audit findings — NOT changed)
1. TITLE DUPLICATION: structured_to_display prepends meta.title as the first display line; PDF renderer strips a leading title line, but /api/shared/{token} web docs previously did not — partially addressed; some formatters (blueprint) hardcode their own heading, harmless.
2. 'Version N' TERMINOLOGY: version numbers exist ONLY in application data (material.versions, agreement records) — no prompt asks the AI to emit 'Version 1'; renderer additionally strips any 'Version N' line defensively. Sign page header no longer displays version. NO active conflict.
3. Title:/Content: STRUCTURE: no prompt requests a 'Title:/Content:' output (all output is schema-driven JSON); the artifacts could only appear if a schema field VALUE contained them — renderer clean_document_lines now converts/strips them. Defense-in-depth, no source conflict found.
4. FORMATTING IN PROMPTS vs RENDERER: several notes/schemas ask for 'UPPERCASE section headings' inside display text (e.g., campaign standard, script displays). This is COMPATIBLE by design (renderer detects uppercase lines as headings) but is a formatting instruction living in prompts that the renderer also owns — consolidation candidate, not a defect.
5. MARKDOWN vs JSON: every generation requires strict JSON (parse_json_response). No resource requests markdown. Fenced ```json responses are tolerated by the parser. No conflict.
6. REVIEW_WARNING is appended deterministically to agreements AFTER generation — it is not in the prompt, so the AI cannot contradict it. Consistent.
7. FOUNDER CONTACT block exists in the RECRUITMENT context builder only; reactivation/activation contexts pass founder_name/org but not the full name/title/email/phone block — emails from those flows depend on their per-type notes for signature detail (known PARTIAL, already in backlog).
